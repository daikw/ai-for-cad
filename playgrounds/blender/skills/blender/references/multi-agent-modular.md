# Library Link モジュール分割と並列サブエージェント運用

シーンを複数エージェントで並列精緻化するための構成。実証済みの成立条件は「ファイル所有権の機械的分割」で、これを崩すと `.blend` の同時編集で必ず壊れる。

## 分割設計

- 意味的なまとまり（店舗・施設・キャラクターなど）ごとに 1 つの `.blend` モジュールに分ける
- 統合 master `.blend` は各モジュールを **Library Link** で読み込むだけにする。master 内にローカルのモジュールオブジェクトを置かない（master validator で 0 件を検証する）
- `manifest.json` を正本として、モジュール一覧と各モジュールの role 別オブジェクト実数を管理する。統合のたびに実数を再集計して反映する
- モジュール内の編集可能範囲は所定の **role Collection** 配下に限定する。新規オブジェクトは必ず対応する role Collection へ格納する

## 編集境界（エージェントへの必須指示）

サブエージェントを起動するとき、以下を毎回明示する:

1. **担当モジュールの `.blend` 以外を読み書きしない**。同じ `.blend` を複数エージェントに割り当てない
2. 共有要素は不変: Root、モジュール外形、master カメラ、コンテキストプロキシ。不変オブジェクトは名前に `DO_NOT_EDIT` を含めて機械的に識別可能にする
3. モジュール外の共有資産（道路・壁・共通ケーブル・グローバル照明・他モジュールの人物）を変更しない
4. 作業後に module validator を実行して PASS を確認する
5. 追加・削除したオブジェクト、マテリアル、ライト、統合側への依頼事項を記録して返す

main エージェントは master・全体レンダ・judge 評価・モジュール間整合性**だけ**を担当し、モジュールの中身には触れない。

## validator は 2 種類

- **module validator**: role Collection 遵守、不変オブジェクトの fingerprint（位置・形状ハッシュ等）差分なし、境界違反なしを検証
- **master validator**: Library Link の解決、モジュール別オブジェクト実数と manifest の一致、master 内ローカルオブジェクト 0 件、カメラの位置とレンズ不変を検証

## wave 運用と統合ループ

1. 同時実行枠を考慮してモジュールを wave に分割する（例: 3 + 2）
2. wave 内の各モジュールを専属サブエージェントで並列実行する
3. wave 完了後、**master を新規 Blender プロセスで開き直して Library Link を再読込**する（既存プロセスの再読込はキャッシュが残る）
4. master validator → 全体レンダ → judge（参考画像・前版・今回レンダを渡す）
5. **judge の BLOCKING だけ**を該当モジュールの担当エージェントへ差し戻す。他モジュールと master はその間ロック（編集禁止）。差し戻し対象外のエージェントに次 wave の blend を先行編集させない（待機）
6. 修正後に再統合・再判定し、BLOCKING が消えるまで 4–5 を繰り返す。PARTIAL（SKILL.md §3 の 3 値判定と同じ用語。軽微指摘＝MINOR もこれに含める）は記録のみ残して次 wave へ進む

## ライト規律

モジュールが各自ライトを足すと Eevee の shadow atlas 上限を超えて shadow buffer 警告が出る。**影を落とすライトは master 側の主要数灯に限定**し、モジュールローカルのライトは色と明るさのみ（`use_shadow = False`）とする。この制約はサブエージェントへの初期指示に含める。

## 反復ループをモジュール単位で回す場合

「各モジュール N 回反復」を発注するときは、1 反復 = 小さな改善 + レンダ + 検証 の単位で定義し、数反復ごとに judge チェックポイントを挟む。各反復の内容と判定をモジュール別ログに残させ、最後に全 4 時点比較（初期 / 中間 / 最終 / 参考画像）を judge に渡して改善が実質的かを確認する。
